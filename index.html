01 / THE PROBLEM

Security tools should not require you to give away the evidence.

Modern security products often depend on cloud analysis. But a URL can contain a private identifier. A system log can expose internal infrastructure. A browsing session can reveal more than a user intended.

Cybersecurity Companion explores a different trade-off: bring useful detection and contextual guidance onto the endpoint, keep sensitive inputs local, and make the results understandable to the person who must act on them.

↳

The design premise
Local processing, explainable signals, explicit user consent, and a lighter operational footprint.

02 / ONE PLATFORM, MULTIPLE LAYERS

From detection to better decisions.

Rather than treating cybersecurity as a single alert, the project connects technical controls with practical guidance and user learning.

01
SUPERVISED CLASSIFICATION

Phishing URL intelligence

Inspects URL structure using engineered signals such as length, special-character density, direct IP usage, suspicious keywords, subdomain depth, HTTPS presence, path depth, and query complexity. A local Random Forest model turns those features into a risk assessment.

04 / THE RAG ASSISTANT

Answers grounded in a local knowledge base.

My contribution centred on the AI assistant and browser experience. For the assistant, the key engineering challenge was not simply adding a chat window. It was building a retrieval path that could find relevant cybersecurity material locally and return it in a useful form without depending on a hosted LLM API.

The dissertation describes a compact embedding model paired with FAISS nearest-neighbour retrieval. The retrieved material supplies context for the response, helping keep the assistant tied to the project's curated knowledge base.

↳

RAG, in plain English
Search trusted reference material first, then use the retrieved context to shape the answer. Retrieval helps grounding, but it does not guarantee that every answer is correct.

05 / THE BROWSER MODULE

A browser that asks a second question: should this be trusted?

The Chromium-based module was designed to make security checks part of the browsing workflow, rather than a separate tool users must remember to open.

  • 01
    Inspect before and during navigation

    URL checks and page-level signals help surface suspicious destinations.

  • 02
    Put downloads behind a decision

    Intercepted download requests can be reviewed, accepted, or cancelled by the user.

  • 03
    Make privacy signals visible

    Known tracker checks and security-header inspection contribute to a clearer page assessment.

  • 04
    Keep analysis off the UI thread

    Background workers and signal-based updates help the interface remain responsive.

07 / ENGINEERING DECISIONS

Built around the real-world constraints.

The dissertation prioritises usable security on ordinary hardware. The engineering choices reflect that constraint rather than assuming a dedicated GPU cluster or a permanent cloud connection.

01

Local-first data path

Threat scoring, retrieval, and application records are designed to remain on-device, reducing the need to transmit sensitive telemetry to external analysis services.

↗︎
02

Asynchronous workloads

Qt worker tasks and signal-based delivery separate expensive analysis from UI rendering, reducing the chance that model work freezes the desktop experience.

↗︎
03

Software-rendering fallback

The design disables hardware acceleration in the described configuration to favour stability on low-specification systems and integrated graphics.

↗︎
04

Local state and model checks

SQLite stores application progress and scan records; the auditor module is intended to make model integrity and changing behaviour more visible.

↗︎

A NOTE ON THE PUBLIC REPOSITORY

The repository is a project snapshot, not the full product.

The public GitHub repository contains code and documentation, but it does not fully reproduce the original project environment. Large model artifacts and some implementation assets were omitted, so parts of the public version may be incomplete or non-runnable as-is. This website explains the system as documented in the dissertation; it does not claim that the GitHub snapshot is a complete, turnkey release.

Security features described in the report are project implementation goals and test claims, not a guarantee that the software is suitable as a production endpoint-protection product. The platform is an academic engineering project and should not replace a professional security stack.
